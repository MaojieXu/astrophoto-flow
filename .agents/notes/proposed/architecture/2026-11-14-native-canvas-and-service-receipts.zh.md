# Agent Note: 原生图与服务收据

Status: proposed

[English](2026-11-14-native-canvas-and-service-receipts.md) | 中文

## Problem

原生工作台已经拥有图文件、自动保存、草稿、撤销、子图与执行。让 FastAPI 再存一份可编辑图，就需要两条保存路径、冲突协调和另一份修订历史。[服务持有图的提案](../../rejected/feature/2026-11-14-canvas-graphs-and-operation-receipts.zh.md)保护了有用的操作与输入保证，但它的图归属会重复产品保留的编辑器。

Windows 参考检出提供了范围更小的集成：FastAPI 通过 HTTPX 调用带认证的 aiohttp 桥接，桥接通过原生 WebSocket 向选定的浏览器页面发送命令，由页面执行原生图操作。本提案采用这个边界，不把参考检出当作已经交付到本仓库的代码。

## Proposal

ComfyUI 拥有可编辑图及其持久化。FastAPI 拥有业务数据、命令准入、输入准备与持久操作收据。本提案取代服务持有图存储的方案，同时保留旧提案的输入快照、幂等与未知结果规则。

### 依赖与归属

工作台使用声明的 Python 3.12 uv 环境。FastAPI、Pydantic 2 与 Uvicorn 提供业务 API；SQLAlchemy 2 访问 SQLite，Alembic 管理 schema。这些是业务依赖，不是恢复引擎素材数据库。HTTPX 调用保留的 aiohttp 引擎路由。

前端保留 Vue、TypeScript、Vite、Tailwind CSS 与现有组件系统。Pinia 拥有原生与本地界面状态；TanStack Vue Query 拥有业务服务数据与缓存。私有 UI（用户界面）包接收宿主控件并发出事件，不导入原生单例。原生 LiteGraph fork 继续作为画布。

FastMCP TS 暴露任务工具并调用 HTTP。服务 OpenAPI 文档为前端和 MCP 消费方生成 TypeScript 客户端与 Zod 校验器；两者都不持有第二份领域实现。

### 画布操作

一次编辑命名 `page_id`、`workflow_id`、`graph_id`、内容标记与 `operation_id`。标记描述当前原生图内容，不是服务持有的保存修订。FastAPI 校验业务引用和节点参数，记录待定收据，再通过 HTTPX 把命令转给引擎桥接。桥接通过 WebSocket 寻址选定页面。

页面在编辑前立即再次检查图身份与内容。节点创建、删除、参数或连线修改通过原生图 API 和原生变更事件执行，保留撤销、草稿与保存行为。过期标记或离线页面明确失败。没有 FastAPI 图保存端点，也不会从服务图副本自动重载。

`canvas_add_data` 把素材或数据集引用解析为准备好的源节点。数据集成员及其顺序在操作时冻结，不复制文件。之后的数据集编辑不会改写已插入的输入。

相同操作 id 和载荷返回已有收据。同一个 id 携带不同载荷是冲突。超时、页面断线或引擎重启可能让结果未知；决定新一次显式尝试前，先查询同一个 id。收据不能仅因命令已发出就宣称成功。

### 调用与证据

用户通过原生 prompt 与队列路径提交整图。外部 MCP agent（智能体）检查和编辑图，不执行整图。引擎拥有调度、进度、取消与原生执行历史。

外部软件调用开始前，其业务收据冻结输入素材与数据集 id、成员顺序、参数、节点与 bundle 版本、输出目标，以及适用时的图哈希或快照。快照是不可变证据，不是另一份可编辑图。原生 prompt id 可用时记录它。无法开始的调用被标为失败，而不是留在待定状态。

服务在科学读取前校验托管输入哈希。字节变化以 `SOURCE_CHANGED` 失败。调用需要固定字节时，把它们复制或 reflink 到运行目录；硬链接无法防止原地修改。引擎接收解析后的路径与快照，不接收数据库句柄。

任务保留有界的状态与等待操作、进度、错误，以及显式且尽力而为的取消。未知是真实结果。显式重试获得链接到前一次的新操作 id。取消后的部分输出仍然可辨识。

收据持久保存操作种类、受影响 id、哈希、耗时、错误与原生 prompt id，不依赖引擎可用性。状态变化追加收据修订。收据持久化不复制原生工作流存储或原生执行历史。

### 原生工作流引用

bundle 移除通过只读适配器检查原生已保存工作流的引用，以及活跃调用和非终态收据。派生引用索引可重建，不能保存图。无法检查原生引用时，拒绝破坏性 bundle 操作。重装精确固定的 bundle 可以恢复原生工作流的可用性。

## Alternatives considered

**在 FastAPI 中保存可编辑图。** 否决：它重复原生保存、草稿与撤销，还需要在两个权威之间同步冲突。持久操作收据可以提供证据而不接管图。

**替换画布框架。** 否决：第二套编辑器需要重建节点、子图、控件、转换与原生执行集成。保留的 fork 已经提供这些能力。

**把 `/prompt` 当作画布编辑 API。** 否决：提交可执行图不会编辑用户打开的浏览器图，也不会进入其撤销历史。实时编辑需要页面桥接。

**自动重试超时命令。** 否决：页面可能已经应用它。先查询已有操作 id；新一次尝试需要显式决定。

**仅在引擎中保存操作收据。** 否决：引擎重启会抹去区分失败与未知结果所需的证据。业务服务持久保存自身收据，不复制原生执行账本。

## Acceptance criteria

- 原生图保存、草稿与撤销仍是唯一可编辑图持久化机制。
- 桥接编辑出现在选定页面，且可以原生撤销；过期目标被拒绝。
- 重复 id 幂等，冲突载荷失败，中断结果仍可查询为未知。
- 调用前冻结数据集输入顺序、软件参数与版本；输入哈希变化在执行前失败。
- 引擎重启后收据仍可读，且不成为另一套图存储。
- bundle 引用检查使用原生已保存工作流，无法核实时拒绝破坏性操作。
- MCP 通过 HTTP 暴露任务工具，不提供整图执行工具。

## Risks

- 实时编辑需要已连接、可编辑的浏览器页面。桥接不提供无界面的图文件编辑。
- 原生保存与撤销语义依赖固定前端；桥接修改必须针对该版本核对。
- 浏览器可能应用编辑后、确认之前消失。持久收据保留不确定性，无法编造确认。
- 共享 Python 依赖让安装失败同时影响引擎、业务服务和检索进程。替换环境前必须检查隔离锁文件导入。
- 新检出仍需实现服务、桥接与 MCP。依赖配置和本提案不会让它们直接可用。
