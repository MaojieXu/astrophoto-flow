# Agent Note: 一个配置文件，一个工作区，显式重启

Status: proposed

[English](2026-11-14-workbench-settings-and-lifecycle.md) | 中文

## Problem

旧工作台把配置拆在工作区 `config.toml`、用户级指针文件、运行时 `processes.json` 和环境变量覆盖里。它能工作，但让“实际运行的是什么”有了好几个答案，而且设置保存不重启就无法生效。新布局在检出或版本化安装中共享一个 Python 环境；它需要更小的契约：一个用户编辑的文件、一个工作区，以及显式而不是推断的重启。

## Proposal

一个工作区恰好有一个用户编辑的 `config.toml`。运行时状态文件记录控制器启动了什么，但它们不是配置，也永远不手工编辑。

[单一 MCP 生命周期提案](2026-11-14-mcp-install-start-stop-workbench.zh.md)维护安装、init/start/stop/status 工具契约与首期 Windows 生命周期和节点查询范围。本记录保留工作区配置与控制器状态归属；原先禁止 MCP stop 的限制由该提案取代。

### 位置与 schema

配置路径来自 `--workspace` 或 `ASTROPHOTOFLOW_CONFIG`；没有用户级默认工作区指针。工作区就是包含 `config.toml` 的目录；运行两个工作区意味着用不同路径运行独立进程组，而不是切换全局默认值。

文件有严格、封闭的 schema：

```toml
[server]
host = "127.0.0.1"
port = 8190

[storage]
data_dir = "data"

[comfyui]
allowed_origins = ["http://127.0.0.1:8188"]

[ingestion]
file_workers = 2
preview_workers = 1
```

没有日志、语言、引擎路径、令牌、数据库、运行时、队列或导入根目录键。`host` 必须是回环 IP 字面量；`port` 是 1 到 65535 的整数；`data_dir` 非空并相对配置文件解析；`allowed_origins` 是非空的回环 HTTP 来源列表，带显式端口；两个 worker 数都是至少为一的整数。未知顶层表或未知键是校验错误，不是被静默忽略的设置。

派生路径是 `data_dir/astrophotoflow.sqlite3`、`data_dir/service.token` 和 `data_dir/.database.lock`。数据目录以仅所有者权限创建；令牌是 32 个随机字节，以仅所有者权限写入一次。日志写到 `logs/`，不写进配置。

工作区布局是 `config.toml`、`data/`、`input/`、`output/`、`logs/`、`context/`、`comfyui-user/`、`comfyui-data/`、`run/` 和 `web/`。`web/` 是引擎提供的已构建前端；它不是第二个配置来源。

### 进程与端口

控制器从后端 uv 环境启动独立的 FastAPI/Uvicorn 业务服务与 aiohttp 引擎进程。服务拥有业务 API 与素材库；ComfyUI 拥有图文件、草稿、保存、撤销、画布与执行。[知识库进程](2026-11-14-agent-knowledge-base-rag.zh.md)是同一环境中后续的独立能力，不是本阶段要伪造的入口。所有监听器都只绑定回环。MCP 保留在根 Node workspace 中，调用固定生命周期动作；实际进程身份与管理归 Python。

配置的服务端口和第一个允许来源端口是偏好，不是保证。如果端口被占用，控制器取下一个空闲端口，并为该次运行把允许来源改写成实际引擎端口。实际端口记录在 `run/processes.json` 中，连同工作区路径、配置路径、生效设置和进程身份。对同一工作区的第二次启动会复用就绪进程；部分或未知状态会被拒绝，而不是重复启动。

### 生命周期

`init` 通过固定安装 worker 下载并准备工作台，再调用共享工作区初始化器。`start` 要求初始化完成，启动服务并等待健康，再启动引擎并等待就绪。检索就绪状态独立，不阻塞画布。`status` 区分安装与运行，并把每个进程报告为受管理、未确认、已退出或未管理。`stop` 拒绝繁忙队列和未知身份，然后排空并停止 pid、创建时间、可执行文件、命令行和工作区标记匹配的进程。它保留安装与工作区数据，确认退出后才报告成功。

`restart` 在进程外运行并记录操作 id。控制器退出前写回执；丢失连接的调用方按操作 id 查询回执，而不是启动第二次重启。原生队列项、软件调用、包预览或未知操作活跃时，重启被拒绝。

一个 MCP 服务器提供 `workbench_init`、`workbench_start`、`workbench_stop` 与 `workbench_status`。Init 创建新工作区，不覆盖已有配置；stop 限于已核实归属的工作区进程，并让 MCP 保持可调用。Restart、任意设置写入和强制停止仍不属于该工具契约。

### 设置与保存语义

设置 API 分别读取已保存文件和生效运行时值。`GET /api/v1/settings/workbench` 返回两者、配置路径、工作区路径、派生地址，以及由配置路径和字节计算的 `config_token`。`PATCH` 需要该令牌；不匹配返回 `409 CONFIGURATION_CONFLICT`；无效值返回带字段路径的 `422 INVALID_CONFIGURATION`；部分写入返回 `503 CONFIGURATION_PARTIALLY_SAVED`，旧文件仍可恢复。

保存永远不重启任何东西。当保存值与运行值不同时 `restart_required` 为真。设置界面分别显示“已保存”和“生效”，并在表单有未保存修改时禁用重启操作。重启端点应用保存值并返回操作 id。

首版只暴露 worker 数、数据目录、host、服务端口和允许来源。选择目录时，平台提供原生选择器就使用它；否则字段接受输入路径。UI 在我们的平台层实现，不编辑冻结的上游设置面板。

### 语言与诊断

语言不是配置键。唯一来源是工作区 `comfyui-user/default/comfy.settings.json` 中的 `Comfy.Locale`。引擎运行时，服务把设置 POST 给引擎；引擎停止时，服务原子地重写文件并保留其他键。UI 重载后生效。

`doctor` 检查解释器、工作区、配置、上次记录的端口和引擎导入。它不安装任何东西，也不自动修复工作区。输出点名失败的检查和建议的修复命令。

## Alternatives considered

**把配置拆成 server、storage、engine 三个文件。** 否决：三个文件可能互相矛盾，部分保存会变成多文件事务。一个严格 schema 的文件让提交保持原子，diff 也可读。

**保留用户级默认工作区指针。** 否决：它是第二个配置文件，让“我在编辑哪个工作区”依赖隐藏状态。`--workspace` 和环境变量是显式的。

**热重载设置。** 否决：worker、数据库路径和引擎绑定地址无法在活进程下安全改变。重启是诚实且可测试的。

**保存后自动重启。** 否决：保存可能是探索性的，可能发生在任务运行时，也可能改变浏览器正在使用的端口。用户决定何时重启。

**把设置放进数据库。** 否决：数据库位于设置所选择的数据目录里，数据库损坏会把设置一起带走。配置文件必须能在服务之外读取和编辑。

**让 UI 编辑上游设置面板。** 否决：前端 fork 是冻结的。我们的面板是扩展点；上游文件保持不变。

## Acceptance criteria

- 一个工作区有一个 `config.toml`；不读取第二个用户级配置或默认工作区指针。
- 未知顶层表或键被拒绝，并给出字段路径。
- 保存是原子的、令牌检查的，并报告 `restart_required`，但不重启。
- 端口回退记录实际端口，并为该次运行改写允许来源。
- `status` 区分受管理、未确认、已退出和未管理进程。
- `stop` 拒绝工作区标记不匹配的进程。
- 队列项、软件调用或未知操作活跃时拒绝 `restart`，其回执可按操作 id 查询。
- 一个 MCP 能下载并初始化、启动、检查和停止其工作台；不暴露 restart、任意设置写入或强制停止。
- 重复 init 保留配置与数据；停止后工作台可再次启动，不要求重新连接 MCP。
- 语言变更走 `Comfy.Locale`，不是配置键。
- 设置 UI 变更留在我们的平台层；不编辑任何上游设置文件。

## Risks

- 另一个进程持有文件时，Windows 原子替换可能失败；保存路径需要重试和可见失败，而不是截断的配置。
- 端口回退可能与另一个进程在探测和绑定之间抢占端口竞争；控制器必须重试并报告最终端口。
- 工作区是目录，移动它会改变相对路径；配置必须从自身位置解析，永远不从当前目录解析。
- 忙碌检测可能漏掉处于状态之间的引擎请求；未知状态必须阻塞重启，而不是猜测。
- 每个进程一个工作区更简单，但对有多个项目的用户不太方便；CLI 仍可以显式运行多个进程。
