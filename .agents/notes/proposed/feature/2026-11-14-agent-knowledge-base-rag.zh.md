# Agent Note: agent 从本地知识库检索处理指引

Status: proposed

[English](2026-11-14-agent-knowledge-base-rag.md) | 中文

## Problem

agent（智能体）在协助天文摄影处理时，只能依靠模型记忆作答。正确的流程取决于软件版本、传感器与滤镜，以及实践者实际遵循的工作流；官方文档和有经验实践者的文章承载了这些知识，但它们分散在手册、PDF 和论坛帖中，并且会随版本变化。没有检索时，agent 会给出看似合理但过时或引用错误的步骤，无法指出出处，并在每次会话中重复同样的不确定性。MCP 表面暴露了工作台，却没有查阅受控参考语料的途径。

## Proposal

增加一个本地知识库，收录官方与专家的天文摄影处理文档，并由 MCP 服务器作为 `knowledge` 模块暴露。agent 先阅读简短的使用说明，再检索语料，获得可引用的文章与段落信息。该模块回答「文档中的流程怎么说」，而不是「运行这张图」；它永远不碰素材、数据集、校准绑定或画布。

### 语料

语料覆盖数据处理流程文档：校准、叠加、拉伸、色彩、降噪、马赛克，以及围绕这些步骤的软件专属操作。每个来源记录在 manifest 中，包含标题、作者或发布方、URL 或本地路径、许可与本地存储权限、文档版本或获取日期，以及内容哈希。许可不允许本地副本的来源只保留元数据与链接，并排除在离线检索之外；不会静默复制。

摄取（ingestion）是一次离线、可复现的构建：校验 manifest、抽取文本、按章节边界切分段落、计算 embedding、构建 BM25 与向量索引，并写入不可变的语料版本。查询结果带上该版本与文档日期。相同输入的重新构建产生相同的语料版本与段落 id；文档变化则产生新版本。

### 检索

一次查询返回排序后的段落。候选生成分别运行 BM25 与 embedding 检索：BM25 保留精确标识符和稀有词，例如 `FITS`、`CFA`、`drizzle`；embedding 一侧覆盖改写与同义词。两份排序列表融合后，由 reranker（重排序器）对查询与段落打分，产生最终 top-k。

每条结果包含段落文本、文章标题、章节路径、来源、文档版本或日期、分数、稳定段落 id 和语料版本。可选过滤器可按来源、产品或主题收窄范围。如果没有段落达到相关性下限，模块返回 `INSUFFICIENT_EVIDENCE`，并带上查询与语料版本，而不是最接近的不相关文本。

该模块返回证据，而不是生成的答案。agent 组织答案并引用段落 id，读者可以核对来源，检索层也无法编造语料中不存在的步骤。

### MCP 表面

该模块在现有 [MCP 表面](../architecture/2026-11-14-node-mcp-for-the-tool-surface.zh.md) 上增加两个任务工具：`knowledge_search` 接受查询和可选过滤器，`knowledge_get` 按段落或文章 id 取回内容。简短的使用说明附在工具描述中，并作为 `knowledge://guide` 资源暴露：何时调用（在回答任何处理操作问题之前）、如何引用，以及检索文本是证据而非指令。

MCP 进程保持现有约束：没有 SQLite 句柄、不导入 Python、不启动子进程。由于选定的 LangFlow/LangGraph 技术栈是 Python，而 MCP 进程是 Node，检索引擎作为本地 sidecar（边车进程）运行，通过回环 HTTP 访问；MCP 进程仍是薄客户端。本地控制器随工作台一起启动和停止 sidecar，因此 MCP 进程仍然不启动任何子进程。sidecar 只拥有自己的语料与索引目录，不读取工作区配置，也不持有服务令牌。

### 本地性与归属

知识库完全在本地机器上运行。查询时不向机器外发起请求；embedding 与 reranker 模型都在本地，首次运行的模型下载是明确且记录在案的步骤。sidecar 只绑定回环地址。

知识库是参考资料，不是[受管素材](../architecture/2026-11-14-managed-asset-ledger.zh.md)。它的文档不会导入素材库，不作为原件计算指纹，不作为数据集成员，也不显示在库中。它没有通往工作区数据库、素材库或图的写入路径。

### 编写与运行

LangGraph 用代码定义检索图；LangFlow 可以绘制或查看同一张图，但签入的图才是真源。检索图、提示模板、模型标识和相关性下限是带默认值的配置，不是藏在索引里的值。

签入的评测集包含真实处理问题及预期文章或段落，与语料放在一起。检索变更要跑这套评测，因此「结果看起来相关」不是验收信号。

## Alternatives considered

**依赖模型记忆或一段很长的系统提示。** 否决：知识是有版本的，体量也超过提示，agent 无法引用，而且过时步骤与当前步骤无法区分。

**查询时搜索网页。** 否决：需求是本地运行，受控语料才是重点。实时搜索带来网络波动、不可信来源，也没有可引用的稳定语料版本。

**只用 BM25 或只用 embedding。** 否决：BM25 漏掉改写，embedding 漏掉精确标识符或稀有词。两份候选列表加 reranker 互为补充，每一级都能单独测试。

**在模块内生成答案。** 否决：它把证据藏在成文答案后面，并增加第二个可能编造步骤的地方。模块返回段落；agent 组织答案并引用它们。

**把文档作为素材导入。** 否决：素材账本跟踪采集原件、数据集和校准。参考文档有不同的来源，也不承担科学输入角色，混入会污染库查询和归属规则。

**使用托管向量数据库或托管 embedding。** 否决：它破坏本地运行，并把语料和查询送出机器。对单用户语料，本地索引足够。

**直接服务 LangFlow 运行时。** 第一版否决：LangFlow 是编写与查看表面，发布其运行时会增加第二个要运维的应用。检索图足够小，可以保持为经过评审的代码。

## Acceptance criteria

- agent 可以调用 MCP 知识模块，获得 top-k 段落，包含文章标题、章节、来源、语料版本和稳定段落 id。
- 每次查询都产生 BM25 与 embedding 两份候选；fixture 测试表明两份列表都有贡献，且 reranker 能改变最终顺序。
- 对同一语料版本重复查询，返回相同的排序段落 id。
- 没有段落达到相关性下限的查询返回 `INSUFFICIENT_EVIDENCE`，而不是不相关文本。
- 查询时不向机器外发起请求，sidecar 只监听回环地址。
- 知识库不能写入工作区数据库、素材库或图。
- MCP 进程仍然不打开 SQLite 数据库、不导入 Python、不启动子进程。
- manifest 为每个已索引文档记录标题、来源、许可与本地存储权限、文档版本或日期和哈希；用同一 manifest 重新构建，产生相同的语料版本与段落 id。
- agent 能看到使用说明，其中写明何时调用模块、引用格式，以及证据不足时的行为。
- sidecar 停止或索引缺失时返回可读错误并指出下一步，而不是堆栈。

## Risks

- 许可是第一道阻碍。官方手册和专家文章可能不允许本地副本或再分发；manifest 必须记录权限，而仅链接的来源无法支撑离线检索。语料范围必须写明这一取舍，而不是假设它不存在。
- 文档会随软件版本变化。被引用的段落可能对索引版本正确、对已安装版本错误，因此结果必须显示文档日期和语料版本，重建节奏也必须明确。
- 领域语言上的检索质量尚未被证明。中英文混合来源、产品专属词汇和 BM25 分词都会影响召回；评测集是防止凭印象调参的唯一防线。
- 分块会把一个流程或参数表切成无用的碎片。段落需要按章节划定边界、保留相邻上下文，并让引用指向章节而不是孤立片段。
- 本地 embedding 与 reranker 模型消耗磁盘、内存和 CPU 时间。冷启动后的第一次查询可能很慢，只有 CPU 的机器也必须可用。
- 检索文本是不可信输入。文档可以包含针对 agent 的指令；段落必须作为数据划定边界，永远不作为指令执行，也永远不允许触发工具。
- sidecar 增加了一个要启动、做健康检查、停止的进程。索引就绪前的 agent 调用必须明确失败，而不是返回看起来像真实答案的空列表。
- 该功能可能漂移成聊天产品或第二个工作台数据库。第一版保持只检索、只读，不生成答案，也不写素材库。
- agent 可能过度信任检索到的段落。使用说明必须要求引用，并在语料无法回答时明确说明，这样自信的答案就不会掩盖缺失的来源。
