# Agent Note: 数据集是有序的子帧集合

Status: proposed

[English](2026-11-14-datasets-and-member-order.md) | 中文

## Problem

旧仓库把数据集当作有序子帧组，并且 `dataset_member.asset_id` 唯一：一个子帧最多属于一个数据集。正是这个约束让校准、曝光合计、回收站引用和目录清单都没有歧义。新仓库还没有数据集契约。无序集合会丢掉叠加所依赖的采集顺序；多对多归属会让“这张帧适用哪套校准”变成按项目回答的问题；而把清单当作第二个事实来源，会与账本漂移。

## Proposal

数据集是一个有名称、有修订号、有序的子帧素材列表。它是校准单位，也是项目引用的单位。一个素材属于零个或一个数据集；从数据集移除它不会删除素材。

### 数据集记录

数据集带 id、名称、可选的库内目录、状态、备注、修订号和清单状态（`pending`、`ready`、`failed`）。它默认是共享素材库对象；项目引用它，而不是复制它。数据集行暴露成员数、完整成员列表的累计曝光、输入就绪状态、引用它的项目，以及每种用途的当前校准。

成员只能是子帧。Master 是独立素材，永远不是数据集成员。数据集通常共享同一种帧用途；混合用途成员是允许的，但会显示为混合，且在成员一致之前不能做数据集级校准。用途永远不会从第一个成员推断。

### 顺序

提交的成员列表是权威。创建或替换成员时，按提交顺序删除并重新插入行，`position = 0..n-1`。追加把新成员放在现有最后位置之后，永远不重排现有列表。用相同的 id 和绑定替换是空操作，不增加修订号。

顺序是数据集身份的一部分。成员相同但顺序不同的两个数据集是不同的输入。API 按 position 顺序返回成员，并拒绝同一请求里的重复 id。

### 一份素材一个数据集

一个子帧素材最多属于一个数据集。把它加入第二个数据集会返回 `409 ASSET_DATASET_OWNERSHIP` 并指出当前拥有者。用户必须先把它从当前数据集移除。素材行显示它的数据集 id 和名称；独立子帧两者都不显示。

这是有意的限制，不是实现捷径。校准状态和证据存在素材上，而一个数据集每种用途只有一个当前绑定。如果同一张帧属于两个带着不同 Dark Master 的数据集，素材的校准状态就会有两个答案。需要同一批帧的项目共享数据集；它们不复制成员关系。

### 曝光与摘要

累计曝光汇总当前每个成员的曝光，而不只是可见页。缺失或未知曝光对合计贡献为零，但会增加未知计数；它永远不会被当作零。数据集行显示成员数、总曝光和校准计数，而不加载成员详情。

### 清单

`dataset.json` 是给外部工具用的生成清单：数据集 id、名称、用途、带相对路径和哈希的有序成员，以及当前校准绑定。数据库是权威；清单从数据库重建，并标记为 `pending`、`ready` 或 `failed`。写清单永远不会创建、重命名或重排成员。如果文件被手工编辑，下一次重建会覆盖它并报告差异。

### 目录整理

素材库可以把数据集的文件放进可预测的目录。整理请求产生一个计划：当前路径、目标路径、素材 id、哈希，以及将要执行的移动。用户用指纹确认计划；执行时逐文件写回执，并报告 `completed`、`partial` 或 `failed`。移动成功的文件在同一事务里更新 `storage_location`。失败会让素材留在旧路径并记录原因；永远不会出现数据库指向一个没有移动的文件。

打开数据集目录是只读便利功能。它永远不改变成员关系或校准。

## Alternatives considered

**使用无序集合。** 否决：叠加和校准配方依赖成员顺序。读取时按文件名或拍摄时间排序，是在猜测用户可能刻意改过的顺序。

**允许多对多归属。** 否决于“一份素材一个数据集”的决定：校准状态、证据、曝光合计和回收站引用都需要成员关系键。跨项目共享数据集已经覆盖了合理的复用场景。

**把清单当作事实来源。** 否决：外部工具可以编辑 JSON，手工编辑的清单无法执行修订检查、归属或回收站状态。清单是投影，不是账本。

**把 Master 放进数据集。** 否决：Master 是可复用的校准素材，不是某次采集的子帧。混在一起会让数据集曝光和成员顺序失去意义，并迫使一个 Master 只能属于一个数据集。

**用虚拟文件夹代替移动文件。** 首版否决：虚拟文件夹避免了文件移动，但不能给外部工具稳定路径，也不能让用户在文件管理器里检查素材库。计划加回执的整理流程让数据库保持权威，同时仍然产生真实路径。

## Acceptance criteria

- 用成员创建数据集会按提交顺序存储，读取时返回相同顺序。
- 追加成员保留现有位置；用重排后的列表替换会重写位置并只增加一次修订号。
- 把素材加入第二个数据集返回 `409 ASSET_DATASET_OWNERSHIP`，并且不改变任一数据集。
- Master 帧不能作为数据集成员加入。
- 累计曝光覆盖完整成员列表，并区分未知曝光与零。
- 删除 `dataset.json` 后可以从数据库重建，而不改变成员关系或顺序。
- 移动文件前必须有整理计划；执行逐文件报告结果，并且永远不会留下过期的 `storage_location`。
- 移除成员保留素材，并让它可加入另一个数据集。

## Risks

- 替换大成员列表会重写每一行 position；事务必须足够快，不阻塞素材库读取，或者使用暂存表。
- 生成的清单在两次重建之间仍可能漂移；UI 必须显示它的状态和最后错误，不能暗示它是实时的。
- Windows 上移动文件可能因打开的文件句柄或长路径失败；回执和旧路径回退是功能的一部分，不是错误路径。
- 一份素材一个数据集会让习惯“同一批 lights 给两个项目”的用户受挫。UI 必须解释共享数据集，而不是复制它。
