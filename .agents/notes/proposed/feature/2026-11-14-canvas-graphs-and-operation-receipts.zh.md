# Agent Note: 画布编辑是带回执的操作

Status: proposed

[English](2026-11-14-canvas-graphs-and-operation-receipts.md) | 中文

## Problem

旧画布用页面 id、工作流 id、图 id 和内容令牌标识一张图，每次编辑都带操作 id。这不是仪式：引擎可以在用户编辑时持有活图，第二个浏览器可以保存同一页面，一次调用可能在开始后中断。没有内容令牌，过期保存会覆盖更新的图；没有操作 id，中断的调用会被重试并产生重复结果。新仓库有原生画布和引擎队列，但没有保存图、编辑、调用快照或回执的契约。

## Proposal

服务拥有保存的图和回执。引擎拥有实时编辑会话并执行图。每次编辑和每次调用都是带 id 和回执的操作。

### 画布文档

一个画布页面有 `page_id`、`workflow_id`、`graph_id`、修订号、内容哈希和所有权标记。一个工作流可以包含多个页面；一个页面有一张当前图。图 JSON 包含节点、边、位置和参数值；它不包含文件路径、令牌或可执行命令。

保存图需要基础修订号或内容令牌。对过期令牌保存返回 `409 CONTENT_CONFLICT`，并保持已存图不变。响应返回新令牌和 diff 摘要。没有静默合并，也没有最后写入者获胜。

服务保存图；引擎的活图是工作副本。打开时，服务返回保存的图和令牌；前端把它加载进引擎。保存时，服务按已安装目录校验节点类型，原子写入图，并记录所有权标记。引擎永远不写服务数据库。

### 编辑

一次编辑命名页面、图、基础内容令牌和 `operation_id`，并包含一个或多个变更：添加节点、移除节点、连接端口、断开、设置参数、移动节点或添加数据源。

`canvas_add_data` 是把素材库素材或数据集变成图输入的唯一路径。它记录素材 id 或数据集 id，把数据集展开成有序成员，并创建源节点而不复制文件。展开在操作发生时冻结；之后的数据集编辑不会改写图。

编辑按 `operation_id` 幂等。重复同一操作返回原回执。过期内容令牌返回 `409`；未安装的节点类型返回点名节点的校验错误；超出 schema 的参数返回字段路径。

### 调用与快照

一次调用命名页面、图内容令牌、选中的输出节点和调用方的 `request_id`。在要求引擎运行之前，服务写入调用记录和 `pending` 状态的回执。记录冻结：

- 图内容哈希和修订号；
- 每个输入素材 id 和数据集 id，以及数据集成员顺序；
- 每个参数值和节点类型/版本；
- 输出节点 id 和预期结果种类。

服务随后解析输入文件。对于托管素材，它校验记录的哈希并读取素材库副本；如果哈希改变，调用在引擎启动前以 `SOURCE_CHANGED` 失败。如果调用需要隔离的输入目录，它把字节固定到那里；硬链接不是固定，因为原地写入会同时改变两个名字。

引擎收到图和解析后的路径，而不是数据库句柄。它的 prompt id 记录在调用上。无法启动的调用被标为失败；它不会留在 pending。

### 任务

任务有 `task_id`、创建它的 `request_id` 和 `operation_id`、状态（`queued`、`running`、`succeeded`、`failed`、`cancelled`、`unknown`）、逐节点或逐项进度、耗时和错误。

`tasks_status` 和 `tasks_wait` 返回状态与进度。`tasks_wait` 有界超时，返回当前状态而不是无限阻塞。取消是显式且尽力而为的；被取消的引擎 prompt 仍可能产生部分输出，回执会记录。重试创建链接到旧 id 的新 `operation_id`；它永远不复用旧 id，因为旧结果可能未知。

当服务无法确认引擎是否启动或完成时，结果是 `unknown`。调用方必须按同一 `operation_id` 查询；启动新调用是用户决定，不是自动重试。

### 回执

回执记录操作 id、种类（`canvas_edit`、`software_call`、`graph_call`、`import`、`export`）、状态、耗时、受影响的页面/图/节点/素材 id、输入哈希、图哈希、适用时的引擎 prompt id，以及带代码和字段路径的错误列表。

回执只追加。状态变化增加回执的新修订，而不是改写历史。引擎停止后回执仍可读；它是尝试过什么的记录，不是实时日志。

## Alternatives considered

**让引擎数据库拥有保存的图。** 否决：引擎会成为已注册图的第二个写者，而它的 schema 不是产品契约。服务保存图；引擎持有工作副本。

**自动保存并让最后写入者获胜。** 否决：两个浏览器标签页，或者 agent 与人类，会悄悄互相覆盖。内容令牌让冲突可见且可恢复。

**发出后不管的调用。** 否决：中断的 HTTP 请求不会留下记录，调用方不知道是否该重试。pending 回执和 prompt id 让结果可查询。

**超时后自动重试。** 否决：第一次调用可能仍在运行。新 id 会复制结果；同一 id 的新尝试需要显式重试记录。

**只把图存成 ComfyUI JSON 文件。** 否决：文件没有修订号、所有权或回执，并发保存会损坏它。文件可以是导出，不是权威。

**用硬链接固定输入。** 否决：对素材库副本的原地写入会同时改变固定后的名字。复制或 reflink 才是真正的固定；仅哈希检查能发现变化但不能阻止变化。

## Acceptance criteria

- 保存的图有页面 id、工作流 id、图 id、修订号、内容令牌和所有权标记。
- 过期图保存返回 `409 CONTENT_CONFLICT`，且不改变已存图。
- 编辑按 `operation_id` 幂等，并拒绝未安装节点类型或超出 schema 的参数。
- 把数据集加入画布会记录其有序成员，且不复制文件。
- 调用在引擎启动前冻结图哈希、输入 id、成员顺序、参数和节点版本。
- 输入哈希改变会在执行前以 `SOURCE_CHANGED` 使调用失败。
- 无法确认结果时任务报告 `unknown`，调用方可按同一操作 id 查询。
- 重试用链接到旧 id 的新操作 id；永不复用旧 id。
- 回执在引擎重启后仍存在，并记录引擎 prompt id。
- 引擎永远不写服务数据库。

## Risks

- 图状态的两个来源（服务和引擎）可能漂移。内容令牌和保存路径必须是唯一的持久化方式，保存后引擎必须重载。
- 长时间调用可能比浏览器会话活得更久；回执和任务必须在要求引擎运行前持久化。
- 取消可能留下部分输出。回执必须说明输出是完整、部分还是未知。
- 固定大数据集可能让磁盘占用翻倍。调用记录必须报告固定字节数，并在回执关闭后清理。
- 引擎队列可能在 HTTP 请求返回后才报告 prompt id；服务必须按 prompt id 对账，而不创建第二次调用。
