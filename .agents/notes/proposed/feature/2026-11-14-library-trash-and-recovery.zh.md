# Agent Note: 回收站把移除和删除分开

Status: proposed

[English](2026-11-14-library-trash-and-recovery.md) | 中文

## Problem

旧素材库没有软删除标记。移除条目会创建一条回收站记录，记住条目类型、来自哪个数据集、成员、还要清理的文件，以及已经清理了什么。正是这条记录让恢复、影响预览和部分清理失败成为可能。素材上的一个布尔值回答不了“移除了哪条数据集归属”“哪些文件已经没了”或“哪个条目失败”；立即删除则既没有恢复路径，也看不到彻底删除的代价。

## Proposal

移除和删除是两个操作。移除素材或数据集会创建回收站条目并把它从活跃素材库隐藏；恢复返回相同身份；彻底删除会删掉托管副本并关闭条目。

### 回收站条目

回收站条目记录：

- `entry_type`：`asset` 或 `dataset`；
- 被移除的 `asset_id` 或 `dataset_id`；
- 对于数据集，记录有序的 `member_asset_ids` 和数据集名称；
- `pending_paths` 和 `cleaned_paths`；
- `cleaned_asset_ids`；
- `cleanup_status`：`pending`、`partial`、`completed` 或 `failed`；
- `removed_at`、操作者和修订号。

条目就是回收站。素材上没有 `in_trash` 布尔值。当一条活跃条目点名某个素材时，它就在回收站里，素材库查询会排除这些 id。

### 移除

移除独立素材会创建素材条目。移除数据集会创建数据集条目并包含它的成员；数据集行和成员关系行从活跃素材库移除，但在数据集条目拥有它们期间，素材不能单独移除。

移除是修订检查的。过期移除返回 `409 REVISION_CONFLICT`。数据集移除会把成员顺序和校准绑定捕获进条目，以便恢复时重建；它不会留下移除了一半的数据集。

### 恢复

恢复用相同的 id、名称、元数据、成员顺序和校准绑定重建素材或数据集。如果 id 已被复用、某个成员已经在另一个数据集里活跃，或者某个校准目标不再可用，恢复会以冲突失败。响应点名冲突条目；它不会先部分恢复再报告成功。

### 彻底删除

彻底删除是两步操作。预览返回素材、托管文件、总字节和阻塞引用，以及一个短期 `preview_fingerprint`。彻底删除需要该指纹和每个条目的当前修订号。如果选择或任何引用发生变化，请求返回 `409 TRASH_STATE_CONFLICT`，并要求重新预览。

只要以下任何东西仍然引用条目，彻底删除就会被阻塞：项目、校准绑定、活跃或排队中的调用、运行中的导出，或者尚未重建的数据集清单。预览列出每个阻塞者；用户必须先移除引用。彻底删除数据集条目会删除成员副本和数据集清单，然后关闭条目。

彻底删除只删除托管素材库副本。它永远不会删除素材库之外的源文件，因为素材库从未拥有过那种文件。每个条目独立处理：被锁定的文件会把该条目标为失败，条目变成 `partial`，重试只针对失败条目。彻底删除永远不会留下指向已删除文件的素材行；只有文件消失后，行才会关闭。

### 身份

恢复的条目保留 id。彻底删除的 id 会退役，永不复用。彻底删除后重新导入同一个源文件会得到带新 id 的新素材，因为旧素材的历史已经关闭。

## Alternatives considered

**给素材加软删除布尔值。** 否决：它记录不了数据集归属、文件清理进度或逐项失败，而且每个查询都要记得这个标记。回收站账本才是记录，不是素材上的过滤器。

**立即删除并依赖操作系统回收站。** 否决：素材库无法预览影响，无法在项目仍引用素材时阻塞彻底删除，也无法报告哪个文件失败。它还会让恢复依赖平台。

**级联删除数据集及其所有成员。** 否决：删除数据集不应该悄悄删掉项目仍然引用的 Master 或素材。回收站条目让成员集合显式可见，并允许用户按整体恢复。

**只从素材库隐藏条目，不建回收站行。** 否决：隐藏不等于可恢复，之后的清理也无法知道哪些文件属于隐藏条目。显式的行才是两步彻底删除安全的前提。

## Acceptance criteria

- 移除素材或数据集会创建回收站条目并把它从活跃素材库排除，但不删除托管文件。
- 恢复返回相同的素材和数据集 id、成员顺序和校准绑定。
- 彻底删除预览报告素材、文件、字节和每个阻塞引用；没有当前指纹的彻底删除会被拒绝。
- 项目、校准绑定、活跃调用、运行中的导出或过期清单引用条目时，彻底删除被阻塞。
- 被锁定的文件产生 `partial` 条目，重试只处理失败条目。
- 彻底删除的 id 永不复用；重新导入同一源文件会创建新 id。
- 任何彻底删除都不会删除托管素材库之外的文件。

## Risks

- 彻底删除会永久删除数据。网页 UI 和 CLI 都必须让预览、指纹和显式确认难以跳过。
- 长时间彻底删除可能中途失败；条目必须保持可检查和可重试，而不是跟着文件一起消失。
- 项目或校准绑定可能在预览和彻底删除之间加入；修订和指纹检查必须同时覆盖两者。
- 回收站可能无限增长。首版需要可见的大小和手动彻底删除，而不是自动定时器给用户惊喜。
