# Agent Note: Reduce the vendored engine to an image-processing core

Status: implemented

English | [中文](2026-11-14-reduce-engine-to-image-core.zh.md)

## Problem

The vendored engine is the full upstream ComfyUI product, not an image-processing library. It still carries diffusion checkpoints, LoRA, VAE, CLIP and text encoders, samplers, ControlNet, model detection and patching, background removal, training and dataset tooling, 3D/mesh/pose, video/audio, global blueprint subgraphs, and the matching frontend model library and assets surfaces. None of that is inert: every start imports the extra-node whitelist and advertises hundreds of node ids in `/object_info`; model folders are created and served over `/models`; and the frontend ships tabs, stores and a default graph for workflows the astronomy product does not run. The product needs image load, scale, crop, mask, composite, preview and save; the rest obscures which half of the engine is live. An earlier deletion wave stopped at the generative runtime because the surviving extras reverse-imported it; that stop line disappeared once those extras were themselves reduced to image-only nodes.

## Decision

Keep only the image-processing surface. `comfy_extras` keeps 28 whitelisted modules plus `color_util.py` and `compositor_blend.py`: post-processing, mask, compositing, rebatch, images, bounding boxes, morphology, logic, resolution, image compare, GLSL, text overlay, color, toolkit, replacements, math, number conversion, painter, compositor, curve, text, loop, primitive, string, preview-any, seed, canny and JSON prompt. `nodes.py` keeps 11 core image classes: `SaveImage`, `PreviewImage`, `LoadImage`, `LoadImageMask`, `LoadImageOutput`, `ImageScale`, `ImageScaleBy`, `ImageInvert`, `ImageBatch`, `EmptyImage` and `ImagePadForOutpaint`. The helper `reshape_latent_to` moved to `comfy/utils.py` so post-processing no longer imports the deleted latent module.

Delete the model and generative runtime instead of leaving it reachable. This removes the 69 model/video/audio/3D/training `comfy_extras` modules, `chainner_models/`, 35 root `comfy` modules (`sd.py`, `model_base.py`, `supported_models*.py`, `model_detection.py`, `model_patcher.py`, `samplers.py`, `sample.py`, `controlnet.py`, `clip_vision.py`, `lora.py`, `hooks.py`, and their support ring) and 12 directories (`comfy/ldm`, `text_encoders`, `cldm`, `t2i_adapter`, `taesd`, `k_diffusion`, `extra_samplers`, `image_encoders`, `audio_encoders`, `background_removal`, `weight_adapter`, `sd1_tokenizer`). AI upscale goes with it: `UpscaleModelLoader` and `ImageUpscaleWithModel` required `CoreModelPatcher`, which required `lora.py`, `model_base.py` and the patcher stack; native `ImageScale`/`ImageScaleBy` remain for astronomy. Background removal also goes: it needed `comfy/ldm/modules` plus a CLIP model, neither of which survives.

Trim the API layer to the image surface. `comfy_api` no longer imports or exposes video, audio or 3D input helpers; `Input` keeps `Image` and `Mask`; `LoadImage` drops the `VideoFromFile` path. `comfy_execution/caching.py` no longer imports model-patcher output detection, and `main.py` no longer imports `model_patcher` for dynamic VRAM.

Delete the model-management HTTP surface: `/embeddings`, `/models`, `/models/{folder}`, `/view_metadata/{folder_name}`, `/experiment/models*`, `/global_subgraphs` and `/global_subgraphs/{id}`. Delete `app/model_manager.py` and `app/subgraph_manager.py`; `folder_paths` now knows only `custom_nodes`, and `main.py` no longer creates model folders. The global blueprint library is part of this deletion; user-created subgraphs, litegraph subgraph editing and the `userdata/subgraphs/` save/load path remain. Keep `/features` because remote config reads it, `/api/jobs` because the queue history reads it, `/extensions` for custom-node web directories, and `/upload/mask` for external mask-editing clients. Keep `/upload/image`, `/view`, `/object_info`, `/prompt`, `/history`, `/queue`, `/interrupt`, `/system_stats` and `/ws`; they are the execution and image API.

Remove the matching frontend surfaces: the model-library and assets sidebar tabs, `modelStore`, model drag-from-asset helpers, the default diffusion workflow, A1111 PNG import, and global-blueprint loading. The new default graph is a single `EmptyImage`; the workflow schema still requires a node, but opening a new workflow no longer stages a checkpoint/CLIP/VAE/KSampler chain. The source tree is now the served frontend: `pnpm build` writes `dist/`, and the launcher is started with `--front-end-root ../frontend/dist` so edits are not masked by the pip package's static tree. The engine declares the remaining runtime in `pyproject.toml` and pins it in `uv.lock`, so a clean `uv sync --frozen` produces a working CPU environment; `uv sync` does not install the frontend build, which is why the launch path must pass `--front-end-root`.

Remove the dependencies that only served the deleted stack: `torchvision`, `transformers`, `tokenizers`, `sentencepiece`, `spandrel`, `torchsde`, `filelock` and `blake3`. Keep `av` because `comfy_extras/nodes_images.py` uses it for AVIF output and the shared decoder in `comfy/utils.py` uses it for EXR inputs and `/view` previews, and keep the remaining small image/runtime dependencies (`einops`, `safetensors`, `kornia`, `PyOpenGL`, `comfy-angle`, `pydantic`, `packaging`).

`torch` stays. Every surviving image node consumes and produces `torch.Tensor` (28 modules import it); it is the tensor runtime, not a training dependency, so the CPU wheel is enough and no CUDA or training stack is installed. The backend manifest also declares the business and retrieval libraries in the shared Python environment, including SQLAlchemy and Alembic for the business API. Those dependencies do not restore model execution or an engine asset database. Service, bridge and MCP behavior follows the active [runtime proposal](../../proposed/architecture/2026-11-13-repository-and-runtime-shape.md); the Windows reference checkout's dual-environment launcher is not this tree's runtime.

## Behaviour that changed

`/object_info` now returns 116 classes, all image/utility nodes; there is no checkpoint, LoRA, VAE, CLIP, sampler, ControlNet or upscale-model class. `/models`, `/embeddings`, `/view_metadata`, `/experiment/models*` and `/global_subgraphs` return 404. The model folders under `models/` are no longer registered or created. A new workflow opens on `EmptyImage` instead of the diffusion default graph; the frontend no longer shows model-library or assets tabs.

## Alternatives considered

**Keep the model runtime and delete only node registrations.** The model classes, patcher, LoRA and hooks would stay reachable through imports and would keep adding branches to every future change, while no astronomy node could use them. Removing the registrations without the implementation is the half-measure that leaves the next reader guessing which half is live.

**Keep the AI-upscale compatibility layer.** `UpscaleModelLoader` wraps a spandrel descriptor in `CoreModelPatcher` only to reuse ComfyUI's device/offload scheduling. Keeping it means keeping `model_patcher.py`, `hooks.py`, `lora.py`, `model_base.py` and roughly 6,500 lines of support ring, and `model_patcher` pulls in `lora` and the model classes. Native `ImageScale` covers the astronomy resize path; a direct spandrel call could be added later without the patcher stack, but that is a new feature, not a reason to keep the diffusion runtime.

**Keep background removal.** It needs `comfy/ldm/modules` and a CLIP encoder, so it cannot coexist with deleting the model runtime; it is also not part of the astronomy image path.

**Keep the frontend model library but delete only backend routes.** The served UI is a build, not the source tree; removing routes without removing their callers and rebuilding makes every model-library action fail at runtime. Removing both sides is the only state that is honest at load time.

## Consequences

The backend is now 202 Python files and 43,705 lines, down from 581 files and 175,906 lines: 379 files and 132,201 lines removed. `comfy/` root has 12 modules, `comfy_extras` has 30 files (28 whitelisted plus two helpers), and `/object_info` has 116 classes. `pytest tests-unit` passes 885 tests. The server was started from the repo `.venv` with the frontend `dist/` and executed a real `LoadImage → ImageScale(128×128) → PreviewImage` prompt successfully; the output was a 128×128 PNG. A clean temporary copy with only `uv sync --frozen` and the same `--front-end-root` also started, served the local page, advertised 116 classes and completed that prompt. EXR inputs and `/view` previews decode through the shared PyAV helper; default EXR previews request WebP while downloads keep the original, and output history refreshes after a job with the assets database off. The template entry points are hidden because no bundled template is executable by the image core.

The earlier route caveat is gone: `/global_subgraphs` and the model routes are now deleted, not left serving a frontend that still calls them. Only the global blueprint library was removed; user subgraphs still load from `userdata/subgraphs/` and can be edited and saved. `openapi.yaml` was not regenerated and still contains descriptions of some removed model/blueprint endpoints; it is documentation, not a route table. The full frontend project run has one timing-sensitive `cameraFraming` failure that passes alone; the fork tooling/CI scripts still report 32 failures because they read the excluded `.github/` tree. The updated subgraph, sidebar, graph-view and module-boundary specs pass.

`manager_requirements.txt` and the optional `--enable-manager` path remain: they are an independent custom-node manager, not part of the model runtime. The image/utility nodes that remain are the extension point for astronomy-specific processing; adding a new image node no longer risks re-registering the diffusion stack.
